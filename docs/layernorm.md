# LayerNorm 优化记录

前向：对 `x[rows, N]` 的每一行求均值和方差，`y = (x - mean) * rstd * gamma + beta`，同时输出 fp32 的 mean、rstd。
支持 fp32 / fp16 / bf16，内部 fp32 计算。代码：`csrc/layernorm/layernorm.cuh`；测试：`tests/test_layernorm.py`（43 个，
含非 2 的幂 shape、N > 16384、非对齐指针）；基准：`benchmarks/bench_layernorm.py`。

## 性能目标

访存密集：每个元素只有几次浮点运算，理想访存量 = 读 x + 写 y（gamma、beta 只有一行，可忽略）。
指标看 DRAM 带宽利用率（理论峰值 512 GB/s），上限参考同等数据量的 device-to-device 拷贝（实测约 465–476 GB/s）。
bench 每次迭代前写一块远大于 L2 的缓冲区清空 L2，避免小数据常驻缓存导致带宽虚高。

## 结构

每个 block 处理一行：线程各自累加 → warp 内 `__shfl_xor_sync` 归约 → 各 warp 结果经 shared memory 再归约。
方差用两遍法（先求均值，再求 `(x - mean)²` 的和），数值上比 `E[x²] - E[x]²` 稳定。

## v1：读三遍

均值、方差、归一化各从 global 读一遍 x。

| shape | 耗时 | DRAM 读 | 说明 |
|---|---:|---:|---|
| 8192×4096 fp32 | 1.02 ms | 359 MB（理想 134 MB 的 2.7 倍） | DRAM 约 94% 繁忙（(359+134) MB / 1.02 ms），但有用带宽只有约 263 GB/s；SM 19% |
| 32768×256 fp16 | 193 µs | 16.8 MB | SM 84.5%，小 N 时指令开销占主导 |

## v2：整行缓存在寄存器

每个线程把负责的元素读进 `float x_reg[kSize]`，之后的三步都从寄存器读，x 只读一遍。kSize 是模板参数，
host 端按 N 选择 `<kThreads, kSize>` 的组合（寄存器数组要求下标是编译期常量）。

第一版写成 `x_reg[i / blockDim.x]`：下标在运行时才知道，寄存器 21 → 63，指令数 6,350 万 → 1.84 亿（2.9 倍），
8192×4096 时 SM 67%、DRAM 约 61%（853 µs），从访存瓶颈变成了指令瓶颈。改为按循环变量 `x_reg[k]` 索引后恢复正常。
小 N（32768×256 fp16）：171 µs，指令 3,170 万，SM 87.9%，仍是指令瓶颈。

## v3：128 位向量化

- `AlignedVec<T, kVec>`（`csrc/common/vec.h`），`kVec = 16 / sizeof(T)`，一条指令读写 16 字节；gamma、beta、y 同样向量化。
- 线程数随 N 选择：小 N 时每线程只处理一个向量（32 / 64 / 128 / 256 线程），大 N 时 kSize 向上取 2 的幂以控制模板实例数量。
- 退回路径：N 不是 kVec 的倍数或任一指针未按 16 字节对齐时用 kVec=1；N > 16384 寄存器放不下，用 v1 的不缓存版本。

32768×256 fp16（ncu）：72.6 µs，DRAM 89.7%；每个请求 16.0 个 sector（128 位读，一个 warp 512 B），
请求数 98,304 = 32768 行 × 3（读 x、读 gamma/beta 各一次、写 y），指令数从 3,170 万降到 570 万。

## 待改进

256×65536 走不缓存路径：x 读三遍，且只有 256 行（256 个 block）不足以让 58 个 SM 都有足够的 warp。
可选方向：整行缓存到 shared memory（64K × 2 B = 128 KB，超出单 block 上限，需要拆分）、
一行拆给多个 block（两阶段归约）、Welford 单遍求均值和方差。

## 经验

1. 访存密集算子先算理想访存量，DRAM 繁忙但读取量是理想值的数倍时，问题是重复读取而不是带宽。
2. 寄存器数组的下标必须在编译期确定，否则会多出大量地址计算或被放到 local memory。
3. 改完 .cu/.cuh 要重新编译再测，确认方法：ncu 中的寄存器数、grid/block 是否与新代码一致。
